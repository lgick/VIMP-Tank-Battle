# Этап 10: `RemoteTanks` — предсказание чужих танков в контакте ✅ выполнен

**Объём**: L · **Репозитории**: `vimp-tanks` · **Зависит от**: этапы 7, 8

## Зачем

Свой танк рисуется «сейчас», чужие — с задержкой интерполяции (100 мс). При
толчке разница вылезает **с обеих сторон сразу**: толкающий въезжает в
нарисованный чужой корпус (клиент контакт вообще не разрешал), а тот, кого
толкают, видит зазор — толкающий нарисован там, где был 100 мс назад.

## Что в tank-battle

`src/client/RemoteTanks.js` (358 строк) — реализация `PredictedSet` для чужих
танков. Два решения, записанных в коде как предупреждения:

1. **Охват намеренно узкий — только контактирующие танки.** Предсказывать всех
   подряд значит показывать дрожание экстраполяции там, где интерполяция
   работает безупречно.
2. **Экстраполяция идёт БЕЗ демпфирования.** Ввод чужого игрока неизвестен, а
   едущий танк держит газ, то есть его скорость за 100 мс примерно постоянна.
   Применить демпфирование модели значило бы тормозить чужой танк на ровном
   месте (`linear: 3` съедает ~23 % скорости за 100 мс).
3. **Упреждение проверки захвата.** Критерий «корпуса уже пересеклись» не
   работает: на экране толкаемого чужой танк нарисован там, где был
   `serverNow − delay`, то есть **ещё не доехал** — контакт не наступит никогда
   и предсказание не включится. Поэтому проверка идёт по авторитетной позиции,
   сдвинутой вперёд по её же скорости; захватить чуть раньше безвредно.

Требует `angvel` чужого танка в кадре — ради этого и вводилась версия v5
(этап 7): без угловой скорости чужой корпус в контакте не доворачивается.

## Что сейчас в плагине

Чужие танки рисуются чистой интерполяцией блока `m1`
(`vimp/packages/engine/core/src/client/interpolator.rs`). Ни предсказания,
ни `angvel` в схеме (`vimp-tanks/src/config/snapshot.js`, блок `m1` — 10 полей).

## Шаги

1. `vimp-tanks/core/src/client/remote_tanks.rs` — реализация `PredictedSet`
   для блока `m1`: чтение строки, правило захвата с упреждением, формат
   рендер-блока.
2. Массовые свойства чужого корпуса — `boxMassProperties` (этап 6), габариты
   из модели (`size * 4` × `size * 3`, как в `core/src/tank.rs`).
3. Интеграция **без демпфирования** — отдельный путь от своего танка,
   у которого демпфирование применяется (`core/src/motion.rs`).
4. Читать `angvel` из кадра (доступен после этапа 7).
5. Рендер-блок наружу, чтобы `parts/Tank.js` рисовал предсказанные трансформы
   контактирующих танков.

## Тесты

Порт `tank-battle/tests/client/RemoteTanks.test.js` (~460 строк). Ключевое:
захват срабатывает по упреждённой позиции (а не по факту пересечения);
вне контакта танк остаётся в `follow`; экстраполяция не применяет демпфирование;
после потери контакта тело плавно возвращается в интерполяцию.

## Готово когда

- `cargo test --workspace`, `npm test` зелёные.
- `npm run sim` — сценарий «два танка в контакте», дрейф в пределах порога.
- `npm run dev` вдвоём (или бот + игрок): при толчке нет ни въезда корпусом,
  ни зазора; танки вне контакта не дрожат.
- Документация: `vimp-tanks/docs/{en,ru}/core.md`.

## Риски

- **Дрожание.** Любое расширение охвата за пределы контакта немедленно
  показывает шум экстраполяции — охват держать узким.
- Демпфирование: соблазн переиспользовать `drive_accel`/`motion.rs` целиком
  приведёт к торможению чужих танков на ровном месте.
- Этап требует v5 (этап 7); без `angvel` доворот корпуса будет предсказываться
  неверно, и реконсиляция начнёт заметно дёргать чужие танки.

## Как сделано

- `vimp-tanks/core/src/client/remote_tanks.rs` — подсистема `RemoteTanks`
  (impl `PredictedBodies`): тела по ключу `модель:gameId` из блока `mN`,
  габариты `size*4 × size*3` и масса из `fixture` модели, захват по
  авторитетной позиции с упреждением `CAPTURE_LOOKAHEAD` (0.2 с) без
  транзитивного замыкания (потолок 6 тел), рендер-строка в форме блока
  модели (11 полей, включая `angvel`).
- Экстраполяция без демпфирования: `linear_damping`/`angular_damping` тела
  остаются нулевыми — отдельный путь от своего танка (`motion.rs`).
- Удаление тел: null-маркеров интерполированный сэмпл не несёт, поэтому
  пропавшая строка присутствующего блока и есть удаление; блок, которого в
  сэмпле нет, тела своей модели не трогает.
- Проводка: `TanksClient::new` регистрирует подсистему в предикторе,
  `track_frame` отдаёт ей свой `gameId` (исключение из множества),
  `set_map`/`reset` её сбрасывают (в отличие от геометрии карты, чужие танки
  заводятся заново кадрами). Типизированный доступ — `Predictor::remote_tanks_mut`.
- Рендер: правки JS не потребовалось — движок дописывает строки подсистем в
  хвост hot-буфера, а `reconstructHot` перекрывает ими одноимённые
  интерполированные строки (этап 8a), так что `parts/Tank.js` получает
  предсказанные трансформы обычным `applyGameData`.
- Тесты: `core/src/client/remote_tanks.rs` (`mod tests`, 22 теста) — чтение
  блока, удаление тел, исключение своего танка, захват с упреждением и без
  замыкания, обломки, потолок множества, реконсиляция, экстраполяция без
  демпфирования, рендер-строки, сброс.
- Сценарий `vimp-tanks/tests/scenarios/contact.json` — два танка в контакте
  (один толкает другого): предсказанный чужой корпус появляется в hot-буфере
  у обоих клиентов, дрейф предикта в пределах порогов. Порог угловой скорости
  ослаблен до 3.5 (остальные как в прочих сценариях): всплеск углового
  импульса приходится ровно на кадр контакта.
- Документация: `vimp-tanks/docs/{en,ru}/core.md` (подсистема, дерево ядра,
  таблица тестов) и `docs/{en,ru}/getting-started.md` (сценарий).

**Не переносилось (этап 11):** `getSimBoxes`/`toRenderPoint` — симуляционные
боксы чужих танков и якорь попадания нужны `ShotPredictor`, они идут
следующим этапом.
